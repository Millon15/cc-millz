# Run and debug configurations

Checked on 2026-10-24 against JetBrains Help labelled 2026.2. XML statements below were checked against
IntelliJ Platform 2025.2 source at `idea/252.23892.409`; they are implementation details, not a cross-version schema.
The concrete examples below are small adaptations of pinned public configuration files. Their originating IDE
versions are unrecorded, so they prove the saved shape, not compatibility with every release. Use the examples
to create files directly, substitute the named project values, then reload and validate in the target IDE.

## Choose the storage

| Storage | Use |
| --- | --- |
| `.idea/workspace.xml`, component `RunManager` | Personal and temporary configurations; do not commit this file. |
| `.idea/runConfigurations/<name>.xml` | Shared configuration in the traditional project directory. |
| `.run/<name>.run.xml` | Shared configuration outside `.idea`; suitable when `.idea` is ignored. |

In **Run > Edit Configurations**, save a temporary configuration, enable **Store as project file**, and inspect
the selected location. Saving a permanent configuration and sharing it are separate operations; the checkbox does
not add anything to version control. IDEA 2019.3 and earlier require the traditional suggested location.
[Run/debug configurations](https://www.jetbrains.com/help/idea/run-debug-configuration.html)

The pinned `RCInArbitraryFileManager.kt` reads `*.run.xml` inside project content and checks for a root
`component` named `ProjectRunConfigurationManager`. `.run` is a useful directory convention; the custom-file
mechanism is not limited to that directory. A configuration outside project content may not load.
The plugin's doctor and backup cover `.run/` and `.idea/`; inspect and back up custom locations separately.

## Read the XML

Shared examples below belong in separate `.run/<name>.run.xml` files. If editing a private configuration,
merge only its `configuration` element into the existing `RunManager` component in `.idea/workspace.xml`;
do not replace the whole file. Here is a PHP Script configuration for a project that already has a CLI interpreter:

```xml
<component name="ProjectRunConfigurationManager">
  <configuration default="false" name="PHP task" type="PhpLocalRunConfigurationType"
                 factoryName="PHP Console" path="$PROJECT_DIR$/bin/task.php" scriptParameters="--check">
    <CommandLine workingDirectory="$PROJECT_DIR$">
      <envs><env name="APP_ENV" value="development" /></envs>
    </CommandLine>
    <method v="2" />
  </configuration>
</component>
```

Evidence: [public PHP Script configuration, pinned revision](https://github.com/mvdbos/php-spider/blob/e676149d0b7b61cee61424dfa849d03ceffb7070/.run/%5BCHECK%5D%20Phan.run.xml), T3, writer version unrecorded.
Change `path`, `scriptParameters`, working directory, and non-secret environment values for the task.
The UI label is **PHP Script**, while this saved factory ID is **PHP Console**.

`RunnerAndConfigurationSettingsImpl.kt` writes `type` from the configuration type ID and `factoryName` from the
factory ID where required. The display label is not necessarily either ID. `default="true"` denotes a template;
`default="false"` can be omitted by newer serializers. Preserve unknown attributes, options, and child elements.

`RunManagerImpl.writeBeforeRunTasks` serializes the before-launch tasks under `method v="2"`, with each task's
provider ID in an `option` element. An empty `method` is not permission to remove an existing build step.
Use the UI to change task order and capture the resulting XML instead of inventing provider IDs.

## Choose the configuration type

These are UI labels, not universal XML type IDs. Installed plugins and editions control availability.

| IDE | Starting point | Check before saving |
| --- | --- | --- |
| IntelliJ IDEA | Application | Main class, module classpath, JRE, working directory. |
| PhpStorm | PHP Script | Script file, CLI interpreter, arguments, working directory. |
| PhpStorm | PHP Remote Debug | Server selection and session IDE key; see `debuggers.md`. |
| GoLand | Go build | Build target, Go SDK, working directory, program arguments. |
| GoLand | Go Remote | Delve address and port; see `debuggers.md`. |
| PyCharm | Python | Script versus module target, interpreter, arguments, working directory. |
| PyCharm | Python Debug Server / Attach to DAP | Select the matching protocol; see `debuggers.md`. |
| WebStorm | Node.js / Attach to Node.js/Chrome | Runtime or inspector host and port. |

Use the linked product help below for each type. For Rider, CLion, RubyMine, framework tests, and third-party
types, use the same storage workflow with a sample generated by that installed product; this reference does not
assert their plugin XML layouts.

## Concrete launch configurations

### Java Application

Set the main class and the existing module whose SDK and classpath should be used. Preserve the build step.

```xml
<component name="ProjectRunConfigurationManager">
  <configuration default="false" name="Java app" type="Application" factoryName="Application">
    <option name="MAIN_CLASS_NAME" value="example.Main" />
    <module name="app.main" />
    <option name="PROGRAM_PARAMETERS" value="--check" />
    <method v="2"><option name="Make" enabled="true" /></method>
  </configuration>
</component>
```

Evidence: [public Java Application configuration, pinned revision](https://github.com/skylot/jadx/blob/b86c58aca10831459a338a8e5771de292697bf8c/.run/jadx-gui.run.xml), T3, writer version unrecorded.
`ApplicationConfigurationType` also confirms the type and factory IDs in the pinned 2025.2 platform source.

### Go build

This package-target example needs an existing Go module and configured SDK. Replace the IDE module name, Go
import path, and entrypoint path together; the IDE module name is not necessarily the Go import path.

```xml
<component name="ProjectRunConfigurationManager">
  <configuration default="false" name="Go app" type="GoApplicationRunConfiguration" factoryName="Go Application">
    <module name="app" />
    <working_directory value="$PROJECT_DIR$" />
    <parameters value="--check" />
    <kind value="PACKAGE" />
    <package value="example.test/app/cmd/service" />
    <directory value="$PROJECT_DIR$" />
    <filePath value="$PROJECT_DIR$/cmd/service/main.go" />
    <method v="2" />
  </configuration>
</component>
```

Evidence: [public Go package configuration, pinned revision](https://github.com/nuclio/nuclio/blob/90a7d6476a7f64db34112d5e10c498fab7e4b8e1/.run/controller-kube.run.xml), T3, writer version unrecorded.
The UI says **Go build**, but this sample uses factory ID **Go Application**. Go Remote has a different type;
its example is in `debuggers.md`.

### Python script

This example uses the selected module's SDK and runs a file, not a module with `python -m`.

```xml
<component name="ProjectRunConfigurationManager">
  <configuration default="false" name="Python app" type="PythonConfigurationType" factoryName="Python">
    <module name="app" />
    <option name="PARENT_ENVS" value="true" />
    <envs><env name="PYTHONUNBUFFERED" value="1" /></envs>
    <option name="SDK_HOME" value="" />
    <option name="WORKING_DIRECTORY" value="$PROJECT_DIR$" />
    <option name="IS_MODULE_SDK" value="true" />
    <option name="ADD_CONTENT_ROOTS" value="true" />
    <option name="ADD_SOURCE_ROOTS" value="true" />
    <option name="SCRIPT_NAME" value="$PROJECT_DIR$/app.py" />
    <option name="PARAMETERS" value="" />
    <option name="MODULE_MODE" value="false" />
    <method v="2" />
  </configuration>
</component>
```

Evidence: [public Python script configuration, pinned revision](https://github.com/mlrun/mlrun/blob/e1775fe5e366f59e153fa0e5b9233c1dc02d48b9/.run/MLRun%20API.run.xml), T3, writer version unrecorded.
Replace `module` and `SCRIPT_NAME`, then verify the resolved interpreter after reload. Remote debug-server
attachment is a separate configuration in `debuggers.md`.

### Node.js

The project must already have a Node.js runtime selected. Set the entry file and its working directory:

```xml
<component name="ProjectRunConfigurationManager">
  <configuration default="false" name="Node app" type="NodeJSConfigurationType"
                 path-to-js-file="$PROJECT_DIR$/app.js" working-dir="$PROJECT_DIR$">
    <method v="2" />
  </configuration>
</component>
```

Evidence: [framework-maintained JetBrains examples, pinned revision](https://github.com/nuxt/nuxt/blob/194b1fe25c56616d98ede9a944974a3e1030875d/docs/3.guide/6.going-further/9.debugging.md), T3, writer version unrecorded.
That source omits `factoryName` for `NodeJSConfigurationType`; retain the omission rather than guessing from
the UI label. Use **Debug** to launch with the debugger; use the attachment example in `debuggers.md` for an
already running inspector.

## Templates, environment, and compound runs

Edit defaults through **Run > Edit Configurations > Edit configuration templates**. Check a newly created
configuration after changing a template; inspect existing configurations individually before promising they changed.
Do not change a template when the request concerns only one named run configuration.

Environment-variable serialization belongs to the configuration implementation. Use its environment editor and
inspect the saved diff; do not assume every type uses the same `envs` element or `.env` support. Review shared XML
for tokens, passwords, local executable paths, and environment-file paths before adding it to Git.
[Application configuration](https://www.jetbrains.com/help/idea/run-debug-configuration-java-application.html)

A **Compound** configuration starts several configurations together without a guaranteed start order.
Use **Before launch > Run Another Configuration** for an ordered predecessor that must finish. A long-running
server used as a predecessor can prevent the next configuration from starting.
[Compound tasks](https://www.jetbrains.com/help/idea/run-debug-multiple.html)

For the Python and Node configurations above, a shared compound file can be:

```xml
<component name="ProjectRunConfigurationManager">
  <configuration default="false" name="App processes" type="CompoundRunConfigurationType">
    <toRun name="Python app" type="PythonConfigurationType" />
    <toRun name="Node app" type="NodeJSConfigurationType" />
    <method v="2" />
  </configuration>
</component>
```

The pinned framework example above supplies the `toRun` shape and omits `factoryName` for the compound type.
Each referenced name and type must match an existing configuration. This adaptation changes only which
configurations the compound launches; it does not add readiness checks or ordering.

After an edit, reload the files into the IDE, confirm the named configuration appears without an error marker,
and inspect its target, interpreter, mappings, and environment. XML parsing only proves syntax; the doctor does
not validate plugin schemas or launch a configuration.
