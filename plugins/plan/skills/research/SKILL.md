# Plan research in Codex

This is a portable adapter for the same Plan package used by Claude Code. Read the plugin's [research command](../../commands/research.md), [researcher prompt](../../agents/answer-researcher.md), and [proover prompt](../../agents/answer-proover.md) before a run. Those files define the phases, artifact formats, adversarial proof standard, verdict tags, and `proof.json` contract. Resolve paths from this skill's directory: the plugin root is `../..`. Do not copy those prompts into another maintained version.

## Select the host

**Claude Code:** If this skill is selected instead of the same-named `/plan:research` command, execute the unchanged [command body](../../commands/research.md) **in this invocation**. Use Claude's `Agent` tool with `subagent_type="plan:answer-researcher"` in Phase 1 and `subagent_type="plan:answer-proover"` in Phase 3; the shared agent files are their registered prompts. Keep the command's artifact-only writes, phase order, contract, verifier, and answer rules. The command file's `allowed-tools` frontmatter is not automatically inherited by a skill; obey the body constraints under the current Claude permissions. Do **not** invoke `/plan:research` from this skill: that may select this skill again and recurse. Do not use the Codex-native mapping below or require `spawn_agent`/`followup_task` in Claude. If the Claude named agents are unavailable, report that the specified pipeline cannot run rather than substituting a reading for proof.

**Codex:** Follow the native mapping below. The command and agent Markdown files contain Claude-specific `Agent(...)`, model, and tool frontmatter. In Codex those are source instructions, **not** executable tool calls or runtime permission controls. Apply the same read-only/artifact-only boundaries through the task you give each native child and the tools actually available; never claim Codex enforces Claude's `allowed-tools` or `disallowedTools` metadata.

## Codex native phase mapping

1. In the target repository, choose a short kebab-case slug (or honor `slug=<name>`) and inspect its committed `.plan.json` once if present. Create only the selected artifact directory, normally `tmp/a/<slug>/`; if the profile configures `artifacts_dir`, use that root consistently in every native child task and artifact. The shared prompts use `tmp/a` as their default example. Read project files but write nothing outside the selected artifact directory during the research run. A profile skill name is available only if that skill is actually installed in Codex; otherwise record its absence instead of pretending to load it.
2. **Research:** call native `spawn_agent` with a bounded task instructing the child to read `agents/answer-researcher.md`, gather cited facts for the verbatim question, and write only its specified files under the artifact directory. Pass `slug`, optional `.plan.json`, branch/PR/ticket context, and the exact repository path. Explicitly require read-only source/DB/network actions; the child may write its research artifacts only. Wait for `RESEARCH_DONE` and inspect `research.md`. If the child needs a follow-up, use native `followup_task` on that child, not a new Claude `Agent` invocation.
3. **Hypotheses:** in the parent, select 1–5 falsifiable claims and write `hypotheses.md` under the same artifact directory as the command specifies. A cited source fact that needs no runtime proof receives a READ-ONLY verdict. If nothing is worth proving, record `NO_HYPOTHESES: research sufficient` and skip the proover.
4. **Proof:** call native `spawn_agent` with a *separate* bounded task instructing the child to read `agents/answer-proover.md`, `research.md`, and `hypotheses.md`; run the real code/query/endpoint with adversarial cases; and write scripts, raw output, `proof.md`, and one `<n>-proof.json` per proof **only** under the artifact directory. Pass the same profile path when present. The child must not edit production code, test suites, config or agent files. Wait for `PROOF_DONE`; use `followup_task` on the same child for corrections or missing contracts.
5. **Answer:** lead with DISPROVED findings. Tag each material claim exactly PROVEN, DISPROVED, INCONCLUSIVE, READ-ONLY, or ASSUMPTION. Link the actual artifact/contract paths and preserve the proover's caveats. A proof without a usable contract is INCONCLUSIVE. Never call a reading or two agents agreeing a runtime proof. A later “fixed” claim requires a fresh verifier exit 0 (or a fresh equivalent artifact run with changed values).

The native child API returns task output; it does not automatically load Claude's named `plan:answer-*` subagent types. Give each child the path to the relevant prompt and its scoped task. When the next phase is blocked on a child, use native `wait_agent` if available; do not poll. If native delegation is unavailable, say that the three-phase Plan pipeline could not be run as specified instead of silently presenting single-agent reading as empirical proof.

## Contract and verifier

The unchanged `scripts/plan-research.sh --slug <slug> --verify <n>` is a **shell verifier**, callable from the target repository after a contract exists; it does not need Claude for `--verify`. Preserve its exit contract: **0** all expected cases match, **1** regression, **2** artifact execution failure, **3** missing/unusable contract. It writes `<n>-proof.verify.out` for executed artifacts and appends `<n>-proof.runs.tsv` with tree and contract hashes for completed comparisons (exit 0 or 1); an execution failure exits before that append. The contract's `expect` is the requirement's oracle, not a value to edit until a test turns green. Only a reviewed `revisions` entry with `case`, `old_expect`, `new_expect`, `requirement`, and `reviewer` changes it.

The script's question-running and `--install` paths are Claude CLI integrations; do **not** use them as the Codex pipeline or assume `--install` is suitable for Codex plugin locations. Run verifier commands only against the intended artifact and project; proof code may execute project tools or containers, so retain normal Codex authorization boundaries. Project-specific `.plan.json` command shapes are hints, not grants of permission.
